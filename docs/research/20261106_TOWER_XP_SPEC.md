## 2. Q1 · 失败到底重不重置回第 1 层？

### 2.1 两条互相矛盾的原文（都是本仓帧）

| 原文 | 出处 | 可能含义 |
|---|---|---|
| 「不过**一旦失败就需要重新开始了**」 | 塔入口对话框（`floor_select_panel.png`） | ① 从第 1 层重来（=可无限刷低层）；② 这一层要重新打（=回到当前层起点） |
| 「很遗憾，这次挑战未能获胜。**你可以重新进入试炼之塔继续挑战**」 | 战败弹窗（`cycle_006.png`） | 「继续挑战」更像**接着当前的层**打，而不是从 1 开始 |

### 2.2 本仓数据的倾向（`LOCAL_INFERRED`，不是证据）
- 昨晚**在 23 层连续战败之后**，收工时的记录仍是「第 23 层」（`state.md:187`）。
  如果战败会归 1，这个数字应该变小。→ 倾向 **"不重置到 1，而是停在当前层"**。
- 但 `选择楼层` 的 1/11/21 预设**点了不改变「你当前到达第 N 层」**（`floor11_pick.png`）→
  这既可能是"预设只是翻页、不改变记录"，也可能是"记录 = 历史最高层，不是当前层"。**两种读法都没被排除。**

### 2.3 一次只读就能定案（**10 秒，零风险，零战斗**）
> 站到塔入口 → 点「挑战试炼之塔」→ **只读对话框上的「你当前到达第 N 层」**，然后关掉。
> 判据：**昨晚最后一次状态就是"23 层战败后"**，所以
> - 读到 **23**（或更大）⇒ **战败不重置**，塔只能往上爬，1–22 层**当前不可重刷**；
> - 读到 **1**（或明显 < 23）⇒ **战败重置回 1**，今晚就能反复刷 1–22 层（这是最值钱的情形）。
> - 读到**别处**（如 24）⇒ 战败后层数还前进了，需再确认一次。
>
> 顺带在同一次操作里点一下「选择楼层」：**看它是弹出一个楼层列表，还是只切换 1/11/21 三页**。
> 前者 = 可以手动选低层（也等于可刷），后者 = 只能向上。

**最优刷法（按 §2 的定案结果分支）**
1. **若"战败重置回 1"**：从 1 层起连刷到"能稳赢的最高层"（昨晚是 **22→23 层** 之间），
   到顶后**故意失败一次触发重置**（前提是确认重置），循环。预计 **50–70 层/小时**；
   8x 不作用于塔也 ≈ **65k–91k XP/h**，作用则 **52 万–73 万 XP/h**。
2. **若"不重置、但「选择楼层」能选低层"**：直接选 **21 层页** 反复刷 21–22 层（已验证过的稳赢区），
   收益同上，但**不需要故意失败**——这是最干净的刷法。
3. **若"不重置、也选不了低层"**：**塔对练级是死资源**（24 层打不过）。此时：
   · 8x 已开 → 回野外（70k/h，今晚的野外不再是"低效"）；
   · 把塔的价值改成"**每天一次的 1300 池子填充 + 胶囊/药剂产出**"，不再投时间。
   → **这条要如实告诉用户**：不是"塔不好"，是"在当前层数 + 当前 8x 状态下，塔的边际收益不明确"。

## 6. 不可写成硬事实

1. **「1300/层」不是"每层都 1300"**——只有一个楼层点的样本，未做低层对照。
2. **「塔经验进池子」**来自代码注释与文档的一手观察，但**没有一次"打塔前后精灵经验条"的对照**；T2 会推翻或确认它。
3. **「战败重置/不重置」两种都没被直接观测**；现有倾向只是"23 层读数可能来源不明"的推论。
4. **「8x 作用于塔」完全没证据**（只有野外一侧的 530 XP 佐证）。
5. **老服「试炼之塔每日一次 / 中途退出保留进度」不适用于本服**（本服一晚 ≥8 层）——引用老服百科会得出错误结论。
6. **VLM 读塔层会错**（14→7 事故）；任何"层数"结论优先用**面板 OCR**，VLM 只作兜底且不得据此写账本。
7. **单层 50 s** 是"连清时"的账本数字；含回血/导航的平均值昨晚约 **3 min/层**（8 层跑 00:26–00:50）。预算用 60–90 s/层、留 2 倍余量。
