## 2. 面板与操作（这一节已有一手材料，可实现）

### 2.1 面板布局（`LOCAL_VERIFIED`，来自视频真帧转录 + `seerauto/skills/parsers.py:1145-1215`）

```
┌────────────────── 经验分配器 ──────────────────[X]┐
│ [精灵头像]   [6 格精灵选择]     序号：008            │
│              ▣ □ □              名字：烈火猴        │
│              □ □ □              等级：17            │
│                                 性格：孤独          │
│                                 升级所需经验值：316  │
│ 该精灵增加 (500) 点经验值   积累经验：18744927       │
│                    [ 确认 ]                        │
└────────────────────────────────────────────────────┘
```
- 已实现的解析器 `parse_exp_allocator` 认这些字段：`序号 / 名字 / 等级 / 性格 / 升级所需经验值 / 积累经验`，
  **数值按几何配对**（caption 与数字分开的 OCR box），读不到就写 `None` 而不是 0（**REPLAY_PASS**，视频真帧验证）。
- 已实现的写入技能 `game.give_exp`：读面板 → 在「该精灵增加」「点经验值」两个 caption 之间的**中点**输入数字 →
  复读确认输入框 → 点「确认」→ **用面板自己的"等级上升 + 池子下降"自证**（`verified=unverified`，只因从未有面板在手）。
- 该技能默认只灌**池子的 50%**（`DEFAULT_FRACTION = 0.5`），因为本服单次上限未知。

### 2.2 推荐操作序列（S1–S8，每步有判据/超时）
| 步 | 动作 | 判据 | 超时/失败处理 |
|---|---|---|---|
| S1 | 进基地（§1.4 路线） | 场景出现"基地手册/家具"类文字 | 30 s；失败换下一候选 |
| S2 | 找**已摆放的分配器**并点它 | OCR 出现 `经验分配器` 或 `积累经验` | 10 s；找不到 → 走"基地手册买家具"分支（**要花 500 赛尔豆，当前赛尔豆=0，需先解决钱**） |
| S3 | 读面板：`等级 / 升级所需经验值 / 积累经验` | 三个数字都拿到；缺一个就重截一帧再认（不许用 None 当 0） | 5 s |
| S4 | 选中目标精灵（6 格里点它） | 面板 `名字/等级` 变成烈焰猩猩 | 5 s；选错就再点一次，不改数字 |
| S5 | 输入数量 | 复读"该精灵增加"变成输入值（`game.give_exp` 已实现这个校验） | 3 s；读不回就不按确认 |

| S7 | 关面板（右上圆形 X） | 回到基地场景 | 5 s |

## 4. 今晚最短路径：从"池子里 1300+"到 Lv42（再往 Lv45）

### 4.1 先把手上的数摆清楚
| 数字 | 值 | 来源 |
|---|---|---|
| Lv41 → Lv42 所需 | **5,830** | 今晚 23:30 精灵面板「升级所需经验」读数（22:56 仍是 6,360，一场 ~530 XP 后变 5,830）**LOCAL_VERIFIED** |
| Lv42 → Lv45 所需（估算） | **≈12,500**（每级约 +5%，按 6,100 + 6,400 累加） | **LOCAL_INFERRED（估算，非实测）** |
| 池子最后确认值 | **5,000**（2026-10-31 17:41 赛尔资料） | LOCAL_VERIFIED（旧）/ 现在 UNKNOWN |
| 10-31 之后可能进池的量 | 塔 8 层 × **1300** = **+10,400**（若塔经验确进池） | LOCAL_INFERRED |
| ⇒ 当前池子估计 | **≈15,000（下界 5,000，上界 ~2 万）** | 必须**先读一次**赛尔资料「积累经验」 |

> **第一件事**：打开赛尔资料读「积累经验」。这一个数字决定今晚全部排期（10 秒，零风险）。

### 4.2 两种情形的最短路径

**情形 A：池子 ≥ 5,830**
1. 进基地 → 找分配器（§1.4）→ S3 读面板。
2. S4 选烈焰猩猩 → S5 输入 **5,830**（或保守一点输入 `池子-1000`）→ S6 确认。
3. S8 复读：**等级变 42、池子减少** ⇒ 成功。**耗时 3–6 分钟，其中 1 分钟是操作，其余是找基地/对话框的时间。**
4. 若还有剩池子，继续灌到 Lv45（每级 ~6,100–6,400）。

**情形 B：池子 < 5,830（例如池子其实只有 1300）**
缺口 = 5,830 − 池子。**补池子的手段按效率排序**：

| 手段 | 单次产出 | 成本 | 每分钟 1000 XP | 备注 |
|---|---|---|---|---|
| **经验接收器**（发明室 **(1850,1130)**，点一次「恭喜你获得了 2000 积累经验」） | **+2000** | 一次点击（几秒） | **≈0.05 min** | **LOCAL_VERIFIED 的悬停证据**；但**是否可无限重复 = UNKNOWN**（需 3 次连点 + 读池子验证）← **今晚最该先试的一条** |
| **塔一层** | **+1300**（进池） | ~50 s + 弹窗 | 0.64 min（8x 生效则 0.08） | 前提是能回低层（见 TOWER_XP_SPEC §2） |
| **每日 50 万逃逸法** | **+500,000** | ~1–2 min（开战即逃） | **≈0.003 min** | 每日一次；需 Lv50 野怪 + 逃跑可用 |
| 野外连战 | 530/场（**进精灵，可能不进池**） | 27 s | 0.85 min（若进池） | 对"填池子"很可能**无效** |

**情形 B 的最短动作序列**：
1. 去发明室 → **连点经验接收器 3 次**（每次之后读池子；若每次 +2000 ⇒ 这就是免费经验泉，缺口立刻补上；若只加一次 ⇒ 记下"一次性"，改用塔）。
2. 池子够了 → 按情形 A 灌等级。

### 4.3 验收（缺一不算成功）
- 面板 `等级` 上升**或** `积累经验` 下降（同一个面板自证）；
- 精灵面板独立复读 `等级` 与 `升级所需经验` 一致；
- **账单**：`池子 before − after ≈ 灌入量`，且 `等级 before→after` 写进 `data/overnight/exp_pour.jsonl`。

## 5. 与其他路线的关系：塔/野外变成"填池子"

分配器跑通后，练级公式从「战斗经验 → 精灵」变成「**填池子 → 分配器 → 精灵**」，
所以塔和野外的价值要按"**每分钟能往池子里放多少 XP**"重排：

| 来源 | 每分钟 1000 XP 池子 | 前提 | 置信 |
|---|---|---|---|
| 经验接收器（发明室 +2000/次） | **≈0.05 min**（若可重复；不可重复则一次性） | 只读点 3 次即可验证 | LOCAL_VERIFIED（单价）/ 可重复性 UNKNOWN |
| 塔（8x 生效时 10400/层） | **≈0.08 min** | 塔吃 8x（UNKNOWN）+ 能回低层（UNKNOWN） | LOCAL_INFERRED |
| 塔（8x 不生效 1300/层） | **≈0.64 min** | 能回低层 | LOCAL_INFERRED（50 s/层实测） |
| 每日 50 万逃逸法 | **≈0.003 min** | HUD 电池/逃跑可用；每日一次 | PUBLIC_UNVERIFIED（视频口径） |
| 野外连战 | **≈0.85 min（且大概率根本不进池）** | — | LOCAL_INFERRED |

**结论**：
1. **优先级变成：经验接收器 → 塔 → 逃逸法 → 野外**。野外从"主力练级"降为"顺手打点道具"。
2. 用户 23:30 说"不要蘑菇怪、要打塔"——在分配器跑通后**塔的正当理由不是练级，而是"填池子 + 出胶囊/药剂"**；
   如果经验接收器可重复，塔连"填池子"都不必要。
3. **塔和分配器是互补不是替代**：塔是**池子的来源**，分配器是**池子的出口**。只有出口打开，塔的 1300/层才真正变成等级。
