## 0. 一页结论

1. **今晚唯一"确定可用"的胶囊补给 = 官方商城 400 XIN豆/个的高级捕捉胶囊**；账号 XIN豆 **5,000** ⇒ 最多 **12 个**。
   赛尔豆 **0** ⇒ 老服那套"道具商店用赛尔豆买初级200/中级400/高级800"**现在不可用**。
2. 还有一条**数量未知但很可能为 0** 的库存：塔每层奖励「3 中级胶囊」（`docs/action-log.md:33`）。
   → 开跑前**必须**先读储存箱/道具面板的胶囊数量（§2 Phase 0）。
3. 抓宠是**战斗内三点击**（道具 → 胶囊 → 投掷）+ **两个判决点**（成功文案 / 挣脱文案）。
   难点不在点击，在**判决文案与胶囊数量读取**——这两样必须先真机采样一次。
4. 第一个练手目标：**皮皮（克洛斯星，Lv1–2）**，预算 **5 个胶囊 / 5 分钟**，预期 1–3 个胶囊到手。
5. **实现前必须标定 3 个东西**（只允许标 3 个的话）：① 战斗界面「道具」按钮 ② 道具面板里「胶囊格 + 使用/投掷」 ③ 战斗中"捕捉结果"文字的 ROI。
   其余 8 项见 §5，属于第二批。

## 2. 抓宠 UI 步骤（逐步可编程化）

> 坐标一律写"已知 / 待标定"。已知的那几个都标了出处；**没标出处的都当待标定**。

### Phase 0 · 前置自检（不进战斗，~15 s）
| 步 | 动作 | 成功判据 | 失败处理 |
|---|---|---|---|
| 0.1 | 确认前台窗口 + 世界态（复用 `ensure_frontmost` / `PRIMARY_WORLD_MARKERS`） | 世界标记连续 2 次 | 中止（不盲点） |
| 0.2 | 读**胶囊库存**：优先读储存箱里胶囊图标+数量；读不到则用"商城可买+已知 XIN豆"估算 | 拿到一个整数 `capsules_left` | 若读不到 → 只允许用预算上界（见 §3）并把该事实写进日志 |
| 0.3 | 读主战 HP / PP（`read_pet_bag` 已有） | HP ≥ 50% 且 PP > 0 | HP 低 → 先「精灵恢复」（(1145,1115)，20 XIN豆，**LOCAL_VERIFIED**） |
| 0.4 | 记录投掷预算 `throws_budget = min(capsules_left - 1, 5)`（**留 1 个**不到万不得已不投） | — | 预算 ≤0 → 中止并报告"胶囊耗尽" |

### Phase 1 · 到位 / 寻怪 / 进战斗（复用现有战斗能力）
| 步 | 动作 | 成功判据 | 超时 |
|---|---|---|---|
| 1.1 | 传送/导航到目标场景（皮皮：**克洛斯星**；项目已多次到达克洛斯星-林间） | 场景标记文字命中 | 30 s |

### Phase 2 · 投胶囊（本能力真正的新增部分）
| 步 | 动作 | 成功判据 | 备注 |
|---|---|---|---|
| 2.1 | 点战斗界面**「道具」**按钮 | 出现道具面板（关键词 `胶囊` / `道具` 且 `战斗` 按钮被遮住） | 坐标 **待标定**（见 §5-A）。已知旁证：`战斗` 按钮模板 ROI `(1710,1130,2040,1260)`（`seerauto/skills/act.py:650`），2×2 布局里「道具」应在**同一行右侧** |

| 2.4 | 等结果（§2 Phase 3） | 见下 | 单次超时 8 s |

### Phase 3 · 结果判决（**必须靠真机采样后写死关键词**）
| 结果 | 预期画面证据（待采样） | 后续动作 |
|---|---|---|
| **捕捉成功** | 战报/弹窗出现 `捕捉成功` / `收服` / `获得了【皮皮】` 之类文案；战斗界面消失或出现奖励弹窗 | 关弹窗 → 进 Phase 4 |
| **挣脱/失败** | 战报出现 `挣脱` / 胶囊破碎动画；战斗继续 | 若 `throws_used < budget` → 可再投一次；否则逃跑收工 |
| **对手逃跑** | 战报出现 `逃跑了` / 战斗结束无奖励 | 收工，不追 |
| **被反杀**（低等级目标基本不会） | 我方 HP→0 或 `你没有可出战的精灵哦` | 立即中止（本仓教训：HP 0 会让后续一切"找不到怪"） |
| **误判安全阀** | 任何一相位 OCR 空/置信 <0.3 | **不重试点击**，先重截一帧再判（有常驻流时 `shot` 会返回近空白图，见 `AGENTS.md` §5.5） |

### Phase 4 · 收尾与自证（~10 s）
| 步 | 动作 | 判据 |
|---|---|---|
| 4.1 | 关掉所有弹窗（按 OCR 文字点：`确认`/`确定`/`我知道了`） | 世界标记恢复 |
| 4.2 | **复读胶囊数量** | 应等于 `before - throws_used`（这就是自证：没扣说明没真投） |
| 4.3 | 打开精灵仓库（`08_pet_storage.png` 的界面）确认新宠入仓 / 入队 | 数量 +1，且名字/等级匹配 |
| 4.4 | 写账本 | `data/overnight/catch_ledger.jsonl`：目标/等级/投掷次数/胶囊类型/结果/前后数量/帧路径 |

## 3. 失败模式与安全边界

| 风险 | 现象 | 规格要求 |
|---|---|---|
| **胶囊耗尽** | 背包 0 / 投掷无效 | 预算 = `min(库存-1, 5)`；用到 0 立即停，**不许去商城自动补货**（花钱操作要人授权） |
| **把高级胶囊当普通胶囊连投** | 单次会话胶囊 -5 | 每次投掷前打印 `capsules_left`，超预算即停 |
| **目标逃跑** | 战报 `逃跑了` | 直接收工，不换场景猛追（稀有宠刷新手册不在本规格范围） |
| **被反杀 / 全员 0 血** | HP 0 | 立即停 + 报告；**不要**继续寻怪（会产生"找不到怪"的假故障） |
| **误把主战放回仓库 / 误放生** | 背包里少了烈焰猩猩 | 见下"禁止自动化" |
| **高等级目标误投** | 对手等级 ≥ 5 或名字不匹配 | 立即逃跑，不投 |
| **面板没开却连点** | 点击落空 | 每次点击后必须"验证面板出现"才允许下一次点击（现有 `_dismiss_dialogs` 同款纪律） |
| **胶囊 UI 在背包（战斗外）还是道具（战斗内）** | 两处都有入口的迹象 | 见 §6 的待标定项；**首选战斗内「道具」路径**，不要在战斗外用胶囊（老服不支持，本服未知） |

### ⛔ 绝对不要自动化的操作（写死在代码里，不进任何 playbook）
1. **放生**（`放生` 按钮，精灵仓库底部）——不可逆风险，必须用户逐只确认。
2. **精英收藏 / 收藏 / 展示**——会改变精灵归属，无业务必要。
3. **出售 / 交易 / 商城购买**（花钱）——除用户显式授权的"买胶囊"外一律禁止。
4. **精灵还原药剂 / 基因重组 / 融合转生 / 元神赋形**——破坏性或 24h 等待，需人决策。
5. **把非目标精灵放回仓库**（尤其主战烈焰猩猩）——只有"明确是本次抓到的新宠"才允许整理。
6. **持续盲点同一坐标**——3 次点击无状态变化 → 停并报告（现有纪律）。

## 4. 最安全的第一个练手目标：**皮皮**（克洛斯星，Lv1–2）

**为什么是它**：野生皮皮 Lv1–2（`seer.61.com` 图鉴：栖息帕诺星系克洛斯星；搜狗百科"初期为 1 至 2 级，可捕捉"），
血量个位数到十几，**不需要削血**、不需要「手下留情」，挣脱风险最低；而且它就是**波克尔/比波**的前身
（同生共死 + 手下留情 的载体，见 `20261106_PUNI_ROSTER_PLAN.md` §2 #4/#9）。

**胶囊数量**：按老服经验，Lv1–2 目标用**初级/中级**通常 1–2 个成功；本服成功率未测（U-B9）。
规格按**最坏 3 个**设计，会话预算 5。

### 一次完整抓宠会话的最小动作序列（14 步，6 个判决点）

```
S1  自检：前台 + 世界态 + 主战 HP≥50% + PP>0                      [判据: 世界标记×2；超时 15s]
S2  读胶囊库存 capsules_left                                      [判据: 得到整数；读不到→用预算上界并记录]
S3  预算 throws_budget = min(capsules_left-1, 5)；若 ≤0 中止        [判据: 打印预算]
S4  导航到克洛斯星（已多次到达）                                    [判据: 场景标记；超时 30s]
S5  寻怪 → 点击进入战斗                                            [判据: 战斗UI出现；超时 20s]
S6  判决点①：OCR 战报首行确认 `对方【皮皮】` 且等级≤3               [判据: 名字+等级；不匹配→按逃跑/打完收工]
S7  点「道具」                                                    [判据: 道具面板出现；超时 5s；失败→重截一帧，不连点]
S8  选胶囊分类 → 点第一格                                          [判据: 选中态/数量文本]
S9  点「使用 / 投掷」                                              [判据: 动画或战报新增行；超时 8s]
S10 判决点②：结果分类（成功/挣脱/逃跑/无变化）                      [判据: §2 Phase3 关键词表]
S11 若挣脱且 throws_used<budget → 回 S9（最多 3 次）；否则逃跑收工
S12 清弹窗（按 OCR 文字点 确认/确定）                               [判据: 世界标记恢复；超时 10s]
S13 判决点③④：复读胶囊数 == before-throws；精灵仓库/队伍 +1        [判据: 两个数字都对]
S14 写 catch_ledger.jsonl（含帧路径）                              [判据: 文件新增一行]
```
**步数**：14 个主步、6 个判决点（S6/S10/S11/S12/S13 中的二分与自证）。
**总预算**：5 分钟 / 5 个胶囊 / 单会话最多 1 个目标种类。

## 6. 「放回仓库」= 下阵 吗？（Lead 要的顺手确认）

**有本机帧，能确认一半：**

`artifacts/round5/08_pet_storage.png`（真机 2400×1600）显示的是**精灵仓库**面板：
- 顶部：`数量 1`；三个 tab：**精灵仓库 / 精英收藏 / 放生仓库**
- 左侧：选中精灵的详情（序号 667 / 名字 **普顿** / 等级 1 / 个体 18 / 性格 冷静 / 六维 攻6 防6 特攻7 特防6 速5 体12）
- 右侧：**8 列 × 5 行 = 40 格/页**，分页 `1/1`，搜索框 + 「全部精灵」筛选；当前只有 1 格被占
- 底部按钮：**「放入背包」**（大）、**「放生」**、**「展示」**、**「收藏」**

由此可判定（`LOCAL_VERIFIED`）：
1. **「放回仓库」的语义 = 把该精灵从背包(出战栏)移入「精灵仓库」**——因为仓库里的对称操作就叫**「放入背包」**。
   所以它**不是**放生，**可逆**（`放入背包` 可拿回来）。
2. **本服的放生入口就在精灵仓库**（`放生` 按钮），不是老服说的"必须在基地建放生舱"；
   而且有 **「放生仓库」** tab（强烈暗示放生后有回收站/反悔区，`INFERRED`，未点过）。
3. 仓库当前 `数量 1`、40 格/页 → **"背包空间"目前不是真实限制**（我们的 4 只 + 1 只仓库宠远未满）。

**仍 `UNKNOWN` 的部分**：放回仓库对**出战队伍**的影响（是否同时下阵、队伍上限几格）——
