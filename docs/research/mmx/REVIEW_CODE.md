## 3. Categories where nothing was found (stated explicitly)

- **Infinite loops / unbounded retries:** none found. Every loop is bounded — `supervise.py`'s
  `while True` is guarded by monotone counters plus the wall-clock deadline; `RunBattle`'s
  `while wins < battles and time.perf_counter() < stall_deadline` is bounded by the stall
  deadline and now additionally by the watchdog; `FarmTower` is bounded by `floors`/`max_seconds`.
  The closest thing to a spin is major #3: a batch that inherits the previous run's battle count
  is judged "effective", which resets the idle clock — bounded only by the deadline, and it is a
  *state* bug rather than an unbounded loop.
- **Duplicate / repeated operations:** the historical double-count of `ledger.batches` is genuinely
  fixed (`record()` owns the counter, `batch_no = ledger.batches + 1`). The `wins`/`floors_won`
  fallback in `runner.py:726` uses `or`, so FarmTower reporting both keys does **not** double-count.
  The one duplicate-writer problem found is the two writers of `counters.tower.floors_cleared`
  (major #6) — the same counter written by two code paths with two different semantics.
- **Resource leaks:** one real leak (the heal snippet's missing `try/finally`, major #9) plus
  excessive daemon churn in `screen_text()` (minor). No SQLite leak: `snapshot()` closes the
  `WorldStore` in a `finally` and `WorldStore.close()` exists (`seerauto/world/store.py:354`);
  `DaemonClient.close()` terminates and reaps its child.
- **"UNKNOWN treated as healthy":** `classify_reason` correctly maps an empty/unknown reason to
  `FAILED`, and `classify_run` correctly maps a missing summary to `FAILED` — both good. The
  supervisor's own fallback path then re-opens the hole from the other side (major #4, exit 0 ⇒
  SUCCESS).
- **Evidence-grade errors:** two — the proof-less "completed" nodes (blocker #1) and the tower
  counter whose absolute value is not justified by its proof string (major #6).

## 4. What looks right

- **The diagnosis.** "Judge a batch by *what it did*, not by whether it exited" is the correct
  framing, and it demonstrably works: the committed `data/supervisor.json` shows the new supervisor
  stopping after **2** NO_WORK batches (`stop_reason: "2 consecutive batches had no schedulable
  work"`), against the 26-batch, 0-failure spin preserved in `data/supervisor.spin_2026-11-04.json`.
  That is the headline bug of the last commit and it is closed.
- **The refusal-before-blocked ordering** in `classify_reason` is subtle and correct: a planner
  refusal embeds every skipped node's reason (`status=blocked: …`, `not in the game world`), so
  matching the refusal *first* is what keeps a nothing-doing batch at NO_WORK instead of BLOCKED.
  The comment explains exactly why — this is the kind of comment that prevents the next person from
  "simplifying" it and re-opening the bug.
- **`classify_run`'s proof requirement** (`and proofs.get(node_id)`) is precisely the AGENTS.md rule,
  and the docstring says why in one line. It should just be the *only* implementation of that rule
  (see blocker #1).
- **One exit code per outcome** (`EXIT_CODES`, with `TIMEOUT = 124` chosen to match coreutils
  `timeout`) is a good, scriptable contract, and the CLI now prints
  `outcome X (exit N): reason` so the supervisor can read the verdict instead of guessing.
- **`Ledger.record()` centralising the counters**, with the explicit note that the numbering must
  not increment `batches` too ("it was, on the first run of this rewrite: two batches reported as
  four"), is the right shape — and the comment protects the next person from re-introducing it.
- **`next_action` being pure** (`now` and `deadline` injected) is what makes the guards testable
  without a game client, and the ordering (deadline → batch cap → cheap streak guards → slow-burn
  idle guard) is sensible.
- **`battle_watch.py` is pure and testable by construction**, `append_snapshot` is explicitly
  non-fatal ("auditing must never break the battle"), and the fingerprint deliberately **excludes
  `turn`** — the exact trap that would have hidden every stuck fight.
- **`_trusted()`'s fix** (`evidence.rank` → `evidence.source.rank`) is a genuine bug fix with an
  accurate docstring: the old code raised `AttributeError` for every evidence object, was swallowed
  by the bare `except`, and returned False for everything, so a verified reading was never protected.
- **The tower counter split** (`floors_reached` vs `floors_cleared`) is the right *model* — separating
  "the number on the wall" from "the number of things I actually beat" is exactly the distinction
  the VLM misread exposed. Only the fact that two writers still share `floors_cleared` is wrong.
- **`game.farm_tower` finally does the actual farming** (`playbooks.py`), and `runner.py` clamps its
  floors against the remaining battle budget so the run cannot report a battle count it never spent.

**Bottom line:** ship-blocking issues are #1 (proof-less completions counted as verified progress)
and #2 (a stuck detector whose fingerprint cannot move, wired in by default, whose false positive
pauses the whole night). Major #3/#4/#5 re-open the "did nothing ⇒ success" hole in three new
places and should be fixed before the supervisor is trusted with another unattended night.
