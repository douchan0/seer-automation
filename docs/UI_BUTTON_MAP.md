# 按钮地图（用"悬停读提示"得到，2026-11-03 真机）

> 图标本身没有 OCR 文字，模板匹配又会被换肤/布局漂移打掉。
> **可靠办法：把鼠标移到图标上停住，客户端会弹出这个按钮的名字** —— 那是可读文本。
> 这个技巧是本轮由用户指出后实现的（`LiveSession.hover_px` + `game.probe_buttons`）。

---

## 1. 技巧本身（怎么用）

```python
from seerauto.live import LiveSession
s = LiveSession(dry_run=False, enable_input=True); s.open()
tip = s.hover_px(1145, 1115, settle_s=1.0)
print(tip["text"])        # -> '精灵恢复'
```

实现要点（都踩过）：

| 要点 | 原因 |
|---|---|
| 坐标是 **game_px**（窗口内设备像素，2400×1600 空间） | 和所有技能/文档一致；不要用屏幕全局坐标 |
| 悬停后 **停 ≥1.0 s** | 提示有淡入；0.55 s 基本读不到 |
| 不用第 1 次结果当结论 | Flash 的提示是**间歇性**的：鼠标必须先"移动过"再停住 |
| `hover_px` 内置 3 次重试（每次横向抖 4px） | 抖一下能让同一个点大概率应答 |
| 返回的是 **OCR 前后差集** | 只取"这次新出现的文字"，天然过滤常驻 UI |
| 有噪声 | 背景动画/聊天滚动也会进差集，所以要么按关键词匹配，要么人工确认 |

**不要把它放进战斗循环**：一次悬停 = 2 次 OCR ≈ 1–2 s。它属于标定/探索。

## 2. 精灵背包的图标行（已验证）

坐标是 game_px。这一行的 `y` 只有很窄一条（约 1100–1131），不同图标略高略低。

| 坐标 | 悬停提示 | 含义 | 证据强度 |
|---|---|---|---|
| (680, 1131) | `身边跟随` | 让精灵跟在角色身边 | 真机 2 次 |
| (860, 1115) | `放回仓库` | 把该精灵放回仓库 | 真机 1 次 |
| (980, 1100) | `精灵图鉴` | 打开图鉴 | 真机 1 次 |
| **(1145, 1115)** | **`精灵恢复`** | **花 XIN豆 把精灵血量补满** | **真机多次 + 点击验证** |

### `精灵恢复` 的完整闭环（已验证）

1. 悬停 (1145,1115) → 提示「精灵恢复」；
2. 点击 → 客户端弹「已花费 **20 个 XIN豆** 使你的精灵重新充满活力了」+ 确认；
3. 关掉弹窗，重读精灵背包 → `4 pets; hp alive=1`（之前是 0）。

这条闭环现在是技能 **`game.heal_pet`**：读背包 → 悬停扫两行 → 点「精灵恢复」→ 复读血量，
只有 HP 真的上升才回 PASS。

> ⚠️ 这是**花虚拟币**的操作（20 XIN豆/次）。默认 `--max-spend 0` 只限制"买东西"，
> 回血属于既有机制内的固定小费；要不要允许自动回血由用户决定。

## 3. 底栏图标（还没用悬停成功标定）

底栏 11 个图标（消息/表情/声音/任务/精灵/地图/商城/徽章/精灵球/仓库/活动）此前是用
**模板匹配**认得（`live_map_icon`、`live_petbag_icon` 等），底栏位置在不同场景会横移约 100px。

本轮试过对底栏做悬停扫描，**提示没有稳定应答**（可能是提示出现在光标上方、被 OCR 的
最小置信度过滤掉）。结论保持：

- 底栏一律**模板定位**，不用固定坐标；
- 若要补底栏的悬停标定，先把 `hover_px` 的 `min_conf` 降到 0.15 并加大 settle 到 1.5 s 再试。

## 4. 已知但不能用悬停解决的

| 项 | 为什么 |
|---|---|
| 客户端启动弹窗（美术包） | 它在**独立小窗口**里，不在游戏画布内 → 用 `list_game_windows()` + 区域截图 + OCR 处理 |
| 地图目的地图标 | 星图里悬停不给提示（实测），只能靠点进去后用场景文字确认 |
| 技能格 | 技能名本身是文字，不需要悬停 |
