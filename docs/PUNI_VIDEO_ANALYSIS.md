## 0. 先说结论（必读）

### 0.1 这份视频不能当作"可执行方案"

视频证明的是：**2026 年 8 月前后，某个账号在 XIN 计划里用 3 天拿到了谱尼**。
它**不证明**：当前 build `1.0.8.9`、当前账号 `hello / <REDACTED_UID>` 也能复制这条路线。

事实上，按 [state.md](state.md) 的实测，路线的**第一个前置条件就已经断了**：

| 前置条件 | 视频要求 | 本机实测（2026-10-31） | 结论 |
|---|---|---|---|
| 交易行 | "三天之内开通交易行"（00:03），全阵容 7 只里 **3 只**只能靠它买 | **未开通**，需 `通关黑暗武斗场 + SPT雷伊 + SPT哈莫雷特`（0/3） | ❌ 断 |
| 赛尔豆 | 交易行挂单价 1.4W / 5W / 5.6W / 10W 量级 | **0** | ❌ 断 |
| XIN豆 | 药水 + 商城道具 | **5,000** | ⚠️ 不足 |
| 积累经验池 | 视频 05:09 画面 **17,226,807** | **5,000**（约 1/3445） | ❌ 断 |
| 主力精灵 | 7 只 100 级 | **小火猴 Lv5 / Lv32**（试炼之塔刷塔中） | ❌ 断 |

**因此：3 天谱尼路线在当前状态下不可达，也不是本队近期目标。** 本文与任务图的价值在于
① 把视频整理成**可被代码消费的状态机**；② 明确哪些节点今天的代码就能吃下；③ 把"视频里是这样"与"本版本支持"严格分开。

### 0.2 从自动化视角看，视频里有三件比"打法"更重要的事

上一版拆解（[plan-from-video.md](plan-from-video.md)）把视频读成了"人类攻略"，因此**漏掉了整套机器可读的战斗状态**。
我逐帧复核后确认，谱尼战斗界面本身就是一台**可读状态机**：

**（1）战斗界面 6 类关键状态全部在画面上、且可 OCR**（证据：`frames/04_seal_1_4/f_00002.png` @ 11:22）

| 状态 | 画面文本 | 位置 | 自动化含义 |
|---|---|---|---|
| 回合数 | `当前回合：3` | 屏幕中上，大字 | **战斗心跳**候选（会随动画闪烁，见下） |
| 我方血量 | `159/361` | 左上 | 决定是否吃药/换人 |
| 我方技能 PP | `使用次数：25/30`（每招各一） | 下方 2×2 技能格 | 决定何时补活力药剂 |
| 敌方行动 | `【谱尼】使用了圣光气，自身充满了圣光气` | 左下「当前战报」滚动区 | **判断"谱尼已空 PP"的官方信号**，无需靠回合数猜 |
| 阶段名 | `虚无封印` / `轮回封印` / `谱尼真身` + `第一命` | 屏幕正中 | **阶段切换无需推断**，直接读 |
| 增减益 | 屏幕最左侧的可叠加图标（如两个「特防」） | 左边缘竖排 | 感应叠了几层可数（验收：`frames/06_seal_5_7/f_00042.png` @ 23:22） |

> ⚠️ **重要修正（书写时接入的新证据）**：`当前回合` 虽是游戏给出的强信号，但**不能当作"存在即战斗、不存在即结束"的二值判据**。
> 工程侧已实测记录在 [KNOWN_PROBLEMS.md](KNOWN_PROBLEMS.md) **P7**：
> 「战斗动画中间帧既无『当前回合』也无『胜利』 → 落进 `idle`」，进而误判并乱点确认框。
> 现有 `scripts/tower.py:30` 正是这么写的（`if '当前回合' in t: return 'battle'`），所以它是**反面教材**，不是可复用范式。
> **正确用法**：`当前回合` 作为**带超时的 last-seen 信号** —— 记住最后一次看到的回合数，
> 只有"持续 N 秒未见 + 未出现结算文本"才升级为 UNKNOWN/ERROR，而不是立刻认定战斗结束。
> 这条同样适用于谱尼的 165 回合长战：中途丢帧、弹窗、动画都会让该文本短暂消失。

**（2）谱尼战极长，现有 40 回合上限直接失效**

我从 OCR 索引里抽出全部 `当前回合` 采样（见 §4.3）：

| 战斗 | 观测到的最大回合数 |
|---|---|
| 封印 1 虚无 | **21**（12:34 = 回合 20，12:40 结束） |
| 封印 2/3/4 | **42**（14:52） |
| 封印 5 轮回（4 条命，**一场连续战斗**） | **125**（23:34 收尾） |
| 谱尼真身 S（命 1–3 一场 + 命 4–6 一场） | **165**（39:45） |

`scripts/tower.py` 与 `scripts/farm_tower.py` 都写死 `for turn in range(40)` 并靠"回合数出现/消失"退场。
**照搬到谱尼战会在战斗中途误判为结束并提前退出。** 这是必须先改的。

**（3）7 只阵容里有 3 只是交易行独占的，且恰是最关键的 3 只**

| 可**不**依赖交易行获得 | 必须**依赖交易行** |
|---|---|
| 魔焰猩猩（小火猴→烈焰猩猩 + 吉尔 融合） | **萨帕克（萨拉）** 5W —— 封印 1 唯一解、真身第一命唯一解 |
| 哈莫雷特（SPT） | **闪光波克尔（闪光皮皮）** 1.4W —— 同生共死，封印 5 / 真身第五命必需 |
| 塞维尔（SPT / 龙王殿） | **卡奥鲁（卡西达）** 5.6W —— 补刀 |
| 纳多雷（SPT） | |
| 克罗达（野生克里 + 技能唤醒 + 还原） | |

即：**即使把 5 只能自给的精灵全部练满，谱尼也打不了**。萨帕克缺席 → 封印 1 无解、真身第一命无解。
这条比"缺钱"更硬：不是"资源不够"，而是"关键装配件在交易行门后"。

### 片段 1 ★★★★★ · 11:16–12:40 封印 1「虚无」—— 最简洁的战斗模板

- **证据**：【A】`frames/04_seal_1_4/f_00002.png` @ 11:22
- **画面**：只带 **萨帕克**（Lv100）单挑谱尼；`当前回合：3`；`159/361`；技能格为
  `七彩龙息 25/25`｜`感应 25/30`｜`精神强化 20/20`｜`相位移动 20/20`。
- **战报实录**（可直接 OCR）：
  ```
  我方【萨帕克】（♀）登场了！
  对方【谱尼】登场了！
  【谱尼】使用了圣灵魔闪光，【状态】：正常
  【萨帕克】使用了感应，特防提升了很多【状态】：正常
  【谱尼】使用了圣灵魔闪光，【状态】：正常
  【萨帕克】使用了感应，特防提升了很多【状态】：正常
  ```
- **打法**（【B】+【A】旁白 11:52「所以咱们这里把血量控到 1/3 左右」）：
  开局连点「感应」叠特防 → 叠够后「精神强化」叠特攻 → 「七彩龙息」输出 → 血量低就吃超级体力药剂。
- **回合数**【A】：11:16 回合 2；11:22 回合 3；…；12:34 回合 20；12:40 结束，约 **21 回合**。
- **为什么它是最有价值的战斗样本**：**单精灵、四技能、无换人、无道具换位**，是全流程里状态空间最小的一场。
  自动化应**从这里开始**，而不是从封印 5 或真身开始。
- **注意**：上游拆解写"单场约 30 回合"，实测约 21 回合 —— 见 §7 修订 R2。

### 片段 2 ★★★★★ · 14:34 / 32:45 「圣光气」= 官方空 PP 信号

- **证据**：【A】战报文本 `【谱尼】使用了圣光气，自身充满了圣光气`（14:34、13:52、25:xx 等多次出现）
- **含义**：谱尼**招式 PP 有限**，当某技能 PP 耗尽后改放「圣光气」。旁白 14:40「他放圣光气就证明…」、32:45「这里证明他已经没有 PP 了」。
- **自动化含义（重点）**：这是全套路的核心判据，**不需要数回合、不需要记技能池**，
  只要在「当前战报」区检出 `圣光气` 字符串即可判定"谱尼进入空 PP 状态"→ 这是**最安全的输出窗口**。
  比"按回合数猜"稳健一个数量级。
- **风险**：谱尼有多招，`圣光气` 也可能只表示"某一招空了"。旁白把它当作全局空 PP【C】。
  该语义歧义记入 U-A6。

### 片段 3 ★★★★★ · 23:22 封印 5「轮回」—— 战斗真实量级

- **证据**：【A】`frames/06_seal_5_7/f_00042.png` @ 23:22
- **画面**：`当前回合：119`；萨帕克 `88/361`；**谱尼血条几乎满**；左侧边缘可见**两个「特防」图标**（感应叠了 2 层）；
  技能格 `相位移动 20/20`｜`精神强化 20/20`｜`乐镜迷踪 5/5`｜`感应 30/30`。
- **三个结论**：
  1. 封印 5 打到 119 回合时谱尼**几乎没掉血** —— "耗 PP"阶段是纯粹的防守消耗，不是输出期。
  2. **buff 图标会叠加显示**，层数可数 → 自动化可以验收"感应叠满了没有"。
  3. `乐镜迷踪` PP 实测 **5/5**【A】，与上游"乐镜迷踪只有 5 PP，别乱按"一致【B】。
- **自动化含义**：一场 125 回合的战斗按每回合 ~2s 计 ≈ 4 分钟/场，**必须允许长回合**且必须能中途恢复
  （OCR 抖动、误点、弹窗都会打断）。这是对现有 `range(40)` 的直接否决。

### 片段 5 ★★★★☆ · 08:40–09:28 交易行 —— 市场是可结构化解析的

- **证据**：【A】`frames/03_spirit_day2a/f_00007.png` @ 09:10（筛选抽屉）、`f_00002.png` @ 08:40（卡西达挂单）
- **界面结构**：
  - 窗口双标签：`交易行` ｜ `官方商城`
  - 筛选抽屉：`名称`（输入框）｜`类型`（全部/精灵/道具）｜`排序`（价格: 低到高）｜`高级筛选`（内含 `性格`、`特性`）｜`重置`｜`搜索`
  - 挂单卡片（每张是一个**独立个体**，不是统一商品）：
    `名称` + `价格 5.6 W` + `Lv17` + `个体 24` + `性格 浮躁` + 右上 `精灵`
- **推断【D】**：`W` = 万，故 5.6W = 56,000。价格旁图标与 `赛尔豆` 的对应关系**未确认**，记入 U-C1。
- **自动化含义（重要，且修正了任务书里的假设）**：
  交易行**不是**"难自动化的 UI" —— 现有 `scripts/fast.py` 已具备
  `click_text()`（按 OCR 文本点击）、`text_input()`（键盘输入）、`click_hover_button()`（悬停后点"前往/购买"）三个原语，
  **足以实现"搜名称 → 读个体/性格 → 按价格排序 → 选中购买"**。
  真正的障碍是 **账号级门槛 + 余额**，不是界面复杂度。
  该结论会改变任务图里"交易行购买=需要新能力"的评级口径（改为：能力可建，但**被前置硬阻塞**）。

### 片段 6 ★★★★☆ · 10:16 / 10:22 每日上限 —— 决定日程排布的唯一硬约束

- **证据**：【A】字幕 `呃然后普尼的封印是一天打四个`（10:16）、`每天最多挑战4次`（10:22）
- **同时出现**：`圣能爆发期间，七大封印全面削弱，挑战失败后可继续进行挑战！`（10:16、10:28、11:10）
- **含义**：7 个封印 + 真身，**按 4 次/天排布，最少 2 天**（视频正是第 2 天打 1–4、第 3 天打 5–7 并顺手真身）。
- **自动化含义**：这是**唯一一个必须跨天持续运行的调度约束**。每日额度用尽 → 必须停机等待重置。
  重置时刻（服务器时区）未知 → U-C3。
- **未确认**：4 次是否**失败也计数**。旁白说"挑战失败后可继续进行挑战"，暗示失败**不**消耗次数【C】。若为真，则重试免费，自动化可以大胆重试；若为假，重试策略需重写。

     这是本文主张的估算口径修正。
